## はじめに

Mac mini で 24 時間稼働する AI アシスタント（[OpenClaw](https://github.com/openclaw/openclaw) + Claude）を運用しています。毎日 15 以上の自動ジョブが走り、スキルファイル（タスク定義）は 42 個。日々の運用で「この変更、大丈夫かな？」と判断が必要な場面が増えてきました。

毎回人間（自分）に聞くのは非効率。かといって AI に全部任せるのも怖い。

そこで **AI 同士で判断を段階的に委任する仕組み** を作りました。コスト・精度・速度のバランスを取りながら、人間が介入するのは「本当に人間じゃないと決められないこと」だけにする設計です。

## 課題：判断のボトルネックは人間だった

運用が安定してくると、AI アシスタントが自律的にやれることが増えます。でも判断が必要な場面で毎回 Discord に「これやっていい？」と聞いてくる。

- cron ジョブのスケジュール変更 → 聞いてくる
- スキルの description 修正 → 聞いてくる
- 設定ファイルの軽微な更新 → 聞いてくる

全部自分で判断してほしい。でも「どこまで自走していいか」の基準がないと、AI は慎重になりすぎるか、逆に暴走するかのどちらか。

## 設計：4 段階のエスカレーションモデル

判断の重要度に応じて、AI 間の 3 段階 + 人間フォールバックの計 4 段階を定義しました。

### レベル 1：自走（レビュー不要）

日常的な操作。確認なしで実行して OK。

- cron ジョブの実行結果確認
- Discord への定期レポート送信
- ファイルの読み取り・検索
- 既存スキルに沿った通常操作

### レベル 2：Codex にセルフレビュー（デフォルト）

中程度の変更。実行前に **OpenAI Codex CLI** に「この変更で問題ないか」を確認する。

具体的には、[Codex MCP サーバー](https://github.com/openai/codex)経由で `codex_ask`（質問専用コマンド）を呼び出し、変更内容とルールを渡してレビューしてもらいます。

- スキルの description 修正（数件）
- 設定ファイル（MEMORY.md / TOOLS.md 等）の更新
- cron の軽微な調整（時間をずらす程度）
- コードレビュー・設計相談

**なぜ Codex か：**
- コストが安い（月 $0.2 程度。gpt-4.1-mini ベース）
- レート制限が緩い
- Mac mini 内で MCP（Model Context Protocol）経由で完結する
- 「ちょっと確認」レベルの質問に最適

他の LLM API（GPT-4o、Gemini 等）でも代替可能ですが、Codex CLI は MCP サーバーとしてローカル完結でき、セットアップが最も簡単でした。

### レベル 3：Claude CLI で確認（最後の砦）

クリティカルな変更のみ。Claude Code CLI の `claude -p "質問"` （パイプモード：対話なしで単発質問を投げるオプション）で確認する。

- LaunchAgent の追加・削除・変更
- sync の仕組み変更
- SSH / ネットワーク設定の変更
- スキル 10 件以上の一括変更
- Notion DB のスキーマ変更
- cron ジョブの新規追加・大幅なスケジュール変更
- API キー・認証情報に触る操作

**制約：1 日 5 回まで。** Claude MAX プランでもレート制限があるため、本当に重要な判断にだけ使います。

### レベル 4：人間に聞く（フォールバック）

AI 同士では決められないこと。

- 課金が発生する判断
- 外部への公開（メール送信、SNS 投稿）
- 取り消せない破壊的操作
- ビジネス上の判断

## 実装のポイント

### 1. コンテキストを渡す

Codex に「これ大丈夫？」と聞くだけでは的外れなレビューになります。Codex は自分のプロジェクトのルールを知りません。**必ず判断基準となるルールを一緒に渡す。**

```
以下のルールに基づいて、この変更をレビューして。
[ルール: CLAUDE.md の該当セクション]
[変更内容: diff や説明]
問題があれば指摘して。
```

**コンテキストなしでの質問は禁止** をルールにしています。判断材料がないと的外れなレビューになるためです。

### 2. エスカレーションパスを明確に

Codex が「これは自分では判断できない」と言ったら claude -p を使う。claude -p でも判断できなければ人間に聞く。**迷ったら上に上げる** のが原則。

### 3. ルールは SOUL.md に書く

AI アシスタントの行動指針ファイル（SOUL.md）に判断基準を明記しています。セッションが変わっても、このファイルを読めば同じ基準で動ける。

## 実際の運用例

### ケース 1：この記事のレビュー

まさにこの記事自体が「Codex ファースト」の実践例です。

1. AI アシスタント（自分の Mac mini 常駐 AI）が記事の下書きを作成
2. Claude CLI 経由で記事全文をレビューに投げた
3. 返ってきた指摘：
   - 「3段階と言いつつ4段階ある」→ 修正
   - 「codex_ask / claude -p の説明が不足」→ 補足追加
   - 「成功した運用例がない」→ この段落を追加
   - 「文体の矛盾」→ トーン統一

レビュー → 修正 → 再レビューのサイクルが、人間を介さず AI 間で完結しました。

### ケース 2：cron ジョブの全面移行

LaunchAgent（macOS のジョブスケジューラ）の設定ファイルが消失し、一部のジョブが動いていなかった。

1. 問題を検出（レベル 1：自走で発見）
2. 全ジョブを OpenClaw cron に移行する判断 → **レベル 3 相当の判断**（インフラ変更）
3. 実行・動作確認・報告をワンセットで

このケースは仕組み導入前の出来事ですが、事後分析すると「影響範囲の確認」「移行手順のレビュー」はレベル 3（claude -p）で十分判断できた内容でした。人間を待つ必要はなかった、という反省から今回の設計が生まれています。

## コスト

| レベル | ツール | 月間コスト | 頻度 |
|--------|--------|-----------|------|
| 1（自走） | なし | $0 | 数十回/日 |
| 2（Codex） | codex_ask (MCP) | ~$0.2 | 数回/日 |
| 3（Claude） | claude -p (CLI) | MAX プラン内 | 最大 5 回/日 |
| 4（人間） | Discord | $0 | 週数回 |

## 学んだこと

### 「修正→確認→報告」をワンセットに

AI に変更を任せる時、「やりました」で終わらせない。**自分で動作確認して、結果を報告するまでが 1 タスク。** これは人間のエンジニアでも同じですが、AI は明示しないとやらない。

### 既存の情報を先に読め

SSH のユーザー名を試行錯誤する前に、TOOLS.md を見れば書いてあった。**ドキュメントに答えがあるのに検索しない** のは AI あるある。ルールとして明文化しました。

### 最初は慎重すぎて困ったが、段階的に解決

導入前の AI アシスタントは何でも聞いてきて正直うっとうしかった。かといって「全部自分で判断しろ」だと暴走が怖い。レベル分けして「ここまでは自走、ここからはレビュー」を明確にしたことで、人間への問い合わせが体感で 7 割減りました。

## まとめ

- **レビューが必要ならまず Codex**：安くて速い。日常の判断はこれで十分
- **Claude は最後の砦**：本当にクリティカルな判断だけ。1 日 5 回まで
- **人間は人間にしかできないことだけ**：課金・公開・ビジネス判断
- **コンテキストなしの質問は禁止**：判断材料がないと的外れになる
- **ルールは明文化して共有**：セッションが変わっても同じ基準で動く

AI エージェントの自律性を上げたいけど暴走は怖い、という人の参考になれば。
