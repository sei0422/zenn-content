## はじめに

Mac mini で 24 時間稼働する AI アシスタントを運用しています。毎日 15 以上の自動ジョブが走り、スキルファイルは 42 個。日々の運用で「この変更、大丈夫かな？」と判断が必要な場面が増えてきました。

毎回人間（自分）に聞くのは非効率。かといって AI に全部任せるのも怖い。

そこで **AI 同士で判断を段階的に委任する仕組み** を作りました。コスト・精度・速度のバランスを取りながら、人間が介入するのは「本当に人間じゃないと決められないこと」だけにする設計です。

## 課題：判断のボトルネックは人間だった

運用が安定してくると、AI アシスタントが自律的にやれることが増えます。でも判断が必要な場面で毎回 Discord に「これやっていい？」と聞いてくる。

- cron ジョブのスケジュール変更 → 聞いてくる
- スキルの description 修正 → 聞いてくる
- 設定ファイルの軽微な更新 → 聞いてくる

**全部自分で判断しろよ！** と思うわけです。でも「どこまで自走していいか」の基準がないと、AI は慎重になりすぎるか、逆に暴走するかのどちらか。

## 設計：3 段階のエスカレーションモデル

判断の重要度に応じて 3 段階を定義しました。

### レベル 1：自走（レビュー不要）

日常的な操作。確認なしで実行して OK。

- cron ジョブの実行結果確認
- Discord への定期レポート送信
- ファイルの読み取り・検索
- 既存スキルに沿った通常操作

### レベル 2：Codex にセルフレビュー（デフォルト）

中程度の変更。実行前に **OpenAI Codex（codex_ask）** に「この変更で問題ないか」を確認する。

- スキルの description 修正（数件）
- 設定ファイル（MEMORY.md / TOOLS.md 等）の更新
- cron の軽微な調整（時間をずらす程度）
- コードレビュー・設計相談

**なぜ Codex か：**
- コストが安い（月 $0.2 程度）
- レート制限が緩い
- Mac mini 内で MCP 経由で完結する
- 「ちょっと確認」レベルの質問に最適

### レベル 3：Claude CLI で確認（最後の砦）

クリティカルな変更のみ。`claude -p "質問"` で Claude Code に直接確認する。

- LaunchAgent の追加・削除・変更
- sync の仕組み変更
- SSH / ネットワーク設定の変更
- スキル 10 件以上の一括変更
- Notion DB のスキーマ変更
- cron ジョブの新規追加・大幅なスケジュール変更
- API キー・認証情報に触る操作

**制約：1 日 5 回まで。** MAX プランのレート制限を保護するため。

### レベル 4：人間に聞く

AI 同士では決められないこと。

- 課金が発生する判断
- 外部への公開（メール送信、SNS 投稿）
- 取り消せない破壊的操作
- ビジネス上の判断

## 実装のポイント

### 1. コンテキストを渡す

Codex に「これ大丈夫？」と聞くだけでは的外れなレビューになります。**必ず判断基準となるルールを一緒に渡す。**

```
以下のルールに基づいて、この変更をレビューして。
[ルール: CLAUDE.md の該当セクション]
[変更内容: diff や説明]
問題があれば指摘して。
```

### 2. エスカレーションパスを明確に

Codex が「これは自分では判断できない」と言ったら claude -p を使う。claude -p でも判断できなければ人間に聞く。**迷ったら上に上げる** のが原則。

### 3. ルールは SOUL.md に書く

AI アシスタントの行動指針ファイル（SOUL.md）に判断基準を明記しています。セッションが変わっても、このファイルを読めば同じ基準で動ける。

## 実際の運用例

### ケース：スキル 32 件の description 一括修正

1. seija（人間）が「description を強化して」と指示
2. AI アシスタントが 32 件の修正内容を作成
3. **本来なら Codex に確認すべきだった**（レベル 2）
4. 実際は確認なしで実行 → 結果的に OK だったが、プロセスとしては改善の余地あり

### ケース：cron ジョブの全面移行

LaunchAgent の plist ファイルが消失し、一部のジョブが動いていなかった。

1. 問題を検出（レベル 1：自走で発見）
2. 全ジョブを OpenClaw cron に移行する判断 → **claude -p で確認**（レベル 3）
3. 実行・動作確認・報告をワンセットで

## コスト

| レベル | ツール | 月間コスト | 頻度 |
|--------|--------|-----------|------|
| 1 | なし | $0 | 数十回/日 |
| 2 | Codex (codex_ask) | ~$0.2 | 数回/日 |
| 3 | Claude CLI (claude -p) | MAX プラン内 | 最大 5 回/日 |
| 4 | 人間 | プライスレス | 週数回 |

## 学んだこと

### 「修正→確認→報告」をワンセットに

AI に変更を任せる時、「やりました」で終わらせない。**自分で動作確認して、結果を報告するまでが 1 タスク。** これは人間のエンジニアでも同じですが、AI は明示しないとやらない。

### 既存の情報を先に読め

SSH のユーザー名を試行錯誤する前に、TOOLS.md を見れば書いてあった。**ドキュメントに答えがあるのに検索しない** のは AI あるある。ルールとして明文化した。

### AI は慎重すぎるくらいがちょうどいい

暴走するよりは「聞きすぎ」の方がマシ。段階的に自走範囲を広げていく設計が安全。

## まとめ

- **Codex ファースト**：日常的な判断は安くて速い Codex に任せる
- **Claude は最後の砦**：本当にクリティカルな判断だけ
- **人間は人間にしかできないことだけ**：課金・公開・ビジネス判断
- **コンテキストなしの質問は禁止**：判断材料がないと的外れになる
- **ルールは明文化して共有**：セッションが変わっても同じ基準で動く

AI エージェントの自律性を上げたいけど暴走は怖い、という人の参考になれば。
